## AI engineering — two distinct capabilities

### 1. AI as a development tool

- Uses AI across analysis, architecture options, implementation, refactoring,
  test design, code review and technical documentation.
- Turns coding standards, domain rules and security checks into reusable
  prompts, commands and quality gates instead of one-off chats.
- Keeps human review and automated checks in the loop: generated code is
  treated as a draft until it is verified.
- Improves output quality through repository context, task decomposition and
  model selection matched to complexity and cost.
- Supports incident investigation with AI-assisted correlation of signals and
  ranked hypotheses, while engineers retain decision ownership.

### 2. AI as a product capability for clients and users

- Designs AI experiences that sit inside real software products: generation,
  retrieval, semantic search, document understanding and guided workflows.
- Builds structured LLM pipelines with validation, retries, timeouts, fallback
  behaviour and human approval for sensitive actions.
- Ships document-intelligence and search capabilities that teams can operate
  through ordinary APIs and product interfaces.
- Introduces evaluation, attribution, safety checks and cost visibility so AI
  features can be governed like any other critical capability.
- Connects model providers as external dependencies with abstraction,
  telemetry and recovery paths — without oversharing platform internals.
